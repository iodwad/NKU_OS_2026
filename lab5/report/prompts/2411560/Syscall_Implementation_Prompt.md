# Lab5 模块一：用户态系统调用功能

以下提示词根据实验任务和本仓库的接口整理，可用于从模块一的起始代码重新核查实现。具体运行结果记录在实验报告第五部分。

## [PROMPT] 任务

在本仓库的 RISC-V RV64 版 uCore 中完成从用户态发起系统调用、由内核分发、再返回用户态的路径。先阅读 `libs/unistd.h`、`user/libs/syscall.c`、`kern/syscall/syscall.c`、`kern/trap/trap.c`、`kern/trap/trapentry.S`，以及 `kern/process/proc.c` 中接收这些请求的函数。以实际源码为准，说明已有实现、需要修复的实现和依赖其他模块的功能。完整的目标是让用户程序可以调用退出、创建和等待子进程、替换程序、让出 CPU、终止进程、获取 PID、输出字符及查看页表等服务。

本次核查 11 个目标函数，即 `exception_handler`、`syscall` 和九个 `sys_*` 处理函数。必要时修复用户封装与内核入口之间的寄存器约定。保留框架已有的其他异常分支、函数签名和系统调用编号，核对从内核线程启动首个用户程序时使用的独立入口。

## [RELY] 可用的接口与前提

- 用户接口定义在 `libs/unistd.h` 和 `user/libs/`。本实验以 `a0` 传编号，`a1` 到 `a5` 顺序传至多五个参数，返回时以 `a0` 取结果。请核对用户包装实际传入的参数个数和 RV64 指针宽度。
- `trap()` 在分发期间把本次现场挂到 `current->tf`。通用寄存器保存在 `tf->gpr`，`tf->epc` 保存异常返回地址。异常返回依赖 `RESTORE_ALL` 正确处理从 S 态返回 U 态或 S 态的情况。
- 进程服务由现有的 `do_exit`、`do_fork`、`do_wait`、`do_execve`、`do_yield`、`do_kill` 承担，当前进程号从 `current->pid` 取得，输出调用 `cputchar`。先确认页表打印函数在当前代码中是否存在定义。
- 对用户缓冲区，用 `user_mem_check` 配合当前地址空间验证整个区间，并区分读和写。结合旧地址空间的释放时机检查用户指针的有效期。内核线程传入的嵌入式程序映像与用户态传入的缓冲区具有不同的生命周期。

## [GUARANTEE] 可观察的结果

1. 每次 `CAUSE_USER_ECALL` 恰好分发一次。返回前 `epc` 已越过四字节的 `ecall`。普通返回由用户在 `a0` 中取得结果。
2. 分发器使用完整 RV64 编号。先检查数组边界，再检查槽位。表外编号返回 `-E_INVAL`，表内空项返回 `-E_UNIMP`。这些请求都应允许调用者继续运行。
3. 系统调用层保持现有进程接口的参数语义。例如 `wait(0, NULL)` 允许省略退出码，提供退出码地址时应检查一个 `int` 的可写范围。允许由最终访问指针的函数完成检查。
4. 对当前版本暂缺的底层服务给出明确的返回行为，并说明补齐依赖的条件。不能仅凭用户测试程序打印了通过标记，就把实际未提供的服务列为完成。

## [SPECIFICATION] 逐项实现与验收

| 函数 | 实现和检查要求 |
|---|---|
| `exception_handler(tf)` | 在 `CAUSE_USER_ECALL` 分支执行 `tf->epc += 4` 并调用 `syscall()`。分别核查用户的 `ecall` 和内核用于启动程序的陷阱入口。 |
| `syscall()` | 从本次 trapframe 取编号和参数，按 `a1` 至 `a5` 构造参数数组，经分发表调用处理函数，把返回值写回 `tf->gpr.a0`。 |
| `sys_exit(arg)` | 将 `arg[0]` 作为退出码交给 `do_exit`。正常退出后该用户现场不应再次执行。 |
| `sys_fork(arg)` | 把当前 trapframe 和其中保存的用户栈指针送入 `do_fork(0, ...)`。核对“父进程返回子 PID，子进程返回 0”分别由哪一层实现。 |
| `sys_wait(arg)` | 按 PID 和可选退出码指针调用 `do_wait`，覆盖等待任一子进程、指定子进程、空指针和不可写指针。 |
| `sys_exec(arg)` | 按名称、名称长度、映像地址、映像大小四项处理请求。用户指针需检查范围及生命周期。核对内核首次启动的调用仍可传递完整 RV64 地址。 |
| `sys_yield(arg)` | 转交 `do_yield`，核查 `need_resched` 在返回用户态前如何被检查。 |
| `sys_kill(arg)` | 将目标 PID 交给 `do_kill`，保留其成功及失败返回值。 |
| `sys_getpid(arg)` | 返回 `current->pid`，同时验证不传实参的用户封装。 |
| `sys_putc(arg)` | 向控制台写出 `arg[0]` 表示的字符，成功返回 0。 |
| `sys_pgdir(arg)` | 有实际打印实现时核对页表输出；实现尚缺时直接验证系统调用的返回值。 |

在 `lab5/code` 下构建内核和用户程序，并记录普通启动结果。用至少一个用户程序跟踪“用户封装 → 异常入口 → 内核处理函数 → 返回寄存器”。用表外编号、表内空槽、高 32 位非零的编号和无效用户指针验证失败路径，再发起一个有效调用以确认内核和进程继续运行。若首次用户态现场需要由调试器补入，记录补入的寄存器、时机和取值，并将这种条件下的测试与原样启动结果分别报告。
