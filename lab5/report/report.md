# 操作系统实验五：用户程序

## 一、实验目的

1. 跟踪一条用户态系统调用，说明内核从哪里取得编号和参数、在哪里保存返回值，以及 CPU 如何回到调用点的下一条指令。
2. 理解第一个用户进程的启动条件。把 ELF 装入内存、建立用户页表、设置第一次 `sret` 要恢复的现场，是三个可以分别检查的步骤。
3. 通过 `fork`、`wait` 和 `exit` 理解父子进程怎样共享一次创建操作的结果，又怎样各自执行、退出并回收资源。扩展练习进一步考察写时复制对页面共享和写权限的影响。

## 二、实验环境

模块一在 Windows 的 WSL2 Ubuntu 环境下交叉编译，目标为 RISC-V RV64，采用 Sv39 分页。编译器为 `riscv64-unknown-elf-gcc 10.2.0`，模拟器为 QEMU 6.2.0，调试器为 `gdb-multiarch 12.1`。QEMU 使用 `virt` 机器和默认 OpenSBI 固件。模块一的代码与测试结果对应 `lab5` 分支提交 [004d675](https://github.com/iodwad/NKU_OS_2026/commit/004d6754bc20850e355d5c8562818a2ecfddbe2b)。

## 三、实验整体流程

Lab4 中的内核线程已经可以切换执行。到了 Lab5，第一次让用户程序运行，还要准备用户页表、用户栈和入口地址。`proc_init()` 建立空闲进程并创建运行 `init_main()` 的内核线程；后者创建执行 `user_main()` 的线程，然后等待子进程。按框架的启动流程，`user_main()` 选取镜像中的 ELF，经过 `kernel_execve()` 和 `do_execve()` 进入 `load_icode()`。内核为该进程构造第一次返回的现场，CPU 才能通过 `sret` 从用户程序入口取指。

用户程序运行后可以通过 `ecall` 请求内核服务。此时用户栈指针和执行位置已经存在，由异常入口保存。多数系统调用可以沿这份现场返回；`fork` 还要为子进程准备一份现场，成功的 `exec` 要将返回位置指向新程序，`exit` 则结束当前进程的执行。这些调用共用一个分发入口，各自对现场和地址空间的处理交给进程管理层。

#### 4.1.1 跟踪一次 `getpid()`

在 `hello` 的串口输出中，`I am process 2.` 里的 2 来自内核的 `current->pid`。沿着这次调用，可以在保存的 `a0` 中先看到系统调用号 18，再看到返回值 2。

| 执行位置 | 此时发生了什么 |
|---|---|
| 用户库 `getpid() → sys_getpid()` | 将编号 `SYS_getpid`（18）放入 `a0`，执行 `ecall`。本实验约定 `a1` 至 `a5` 传参数，这个调用不需要参数。 |
| 汇编入口 `__alltraps` 和 `trap()` | 在进程内核栈上保存寄存器及 CSR。`trap()` 暂存原来的 `current->tf`，把本次现场挂到该字段，C 分发函数因此能取到用户寄存器。 |
| `exception_handler() → syscall()` | 识别 `CAUSE_USER_ECALL` 后将 `tf->epc` 加 4，跳过这条四字节的 `ecall`。`syscall()` 按保存的 `a0` 查表，调用内核的 `sys_getpid()`，把结果 2 写入 `tf->gpr.a0`。 |
| `__trapret → RESTORE_ALL → sret` | 恢复时将现场里的 2 装回 CPU 的 `a0`，将更新后的地址装入 `sepc`。用户程序从 `ecall` 的下一条指令继续，用户库读出返回值。 |

这里沿用了框架的 `CAUSE_USER_ECALL` 分支和 `RESTORE_ALL`。`RESTORE_ALL` 根据保存的 `sstatus.SPP` 判断返回的特权级。返回 U 态时，它先把退栈后的内核栈指针写入 `sscratch`，供下一次从 U 态陷入时使用，最后才恢复用户 `sp`。返回 S 态时跳过保存内核栈指针的步骤，沿用异常入口已清零的 `sscratch`。这一步解释了用户程序有自己的栈时，下一次系统调用仍能找到本进程的内核栈。[异常处理](../code/kern/trap/trap.c) · [汇编入口和返回](../code/kern/trap/trapentry.S)

#### 4.1.2 用户封装和分发器的修改

原用户库用可变参数实现统一入口，每次固定取五个参数。`getpid()` 没有实参，`putc` 只传一个字符，继续调用 `va_arg` 会读取调用者没有传入的参数。原汇编还用 `sd` 把八字节寄存器写入四字节的 `int ret`，写入范围超出了变量。我们把内部入口改为五个固定宽度的参数，由各用户封装将未用位置填零。`a0` 用读写约束 `"+r"` 声明，进入汇编时提供编号，退出时直接取回结果，再转为用户接口约定的 `int`。[用户库实现](../code/user/libs/syscall.c)

内核原来先把 `tf->gpr.a0` 赋给 `int num` 再检查范围。这在 RV64 上会丢掉高 32 位。例如 `(1ULL << 32) | SYS_getpid` 的低位正好是 18，截断后就会误入 `getpid`。现在用 `uintptr_t` 检查完整编号，先判范围，再判对应表项，最后才调用函数指针。表外编号返回 `-E_INVAL`（−3），表内预留但尚未注册的编号返回 `-E_UNIMP`（−20）。两种错误都经 `a0` 返回，调用者还可以发起下一次请求。[内核分发器](../code/kern/syscall/syscall.c) · [编号定义](../code/libs/unistd.h)

分发器的两次检查顺序如下。先排除表外编号，下一行对 `syscalls[num]` 的访问才有定义。

```c
uintptr_t num = tf->gpr.a0;
if (num >= NUM_SYSCALLS) {
    tf->gpr.a0 = -E_INVAL;
    return;
}
if (syscalls[num] == NULL) {
    tf->gpr.a0 = -E_UNIMP;
    return;
}
```

#### 4.1.3 九个处理函数怎样使用参数

下面的 `arg[0]` 至 `arg[4]` 分别来自用户寄存器 `a1` 至 `a5`。加上异常入口和统一分发器，本模块共涉及 11 个函数。

| 内核函数 | 编号 | 参数与处理 |
|---|---:|---|
| `sys_exit` | 1 | 将 `arg[0]` 转成退出码交给 `do_exit()`。正常退出后，调用进程的用户代码不再继续。 |
| `sys_fork` | 2 | 调用 `do_fork(0, tf->gpr.sp, tf)`。保存的 `sp` 指向父进程用户栈，后续由进程层为子进程准备现场和地址空间。 |
| `sys_wait` | 3 | 将 PID 和可选退出码指针交给 `do_wait()`。`wait()` 传 `0, NULL`，表示等待任一子进程；`waitpid()` 可指定 PID。非空指针由 `do_wait()` 在当前地址空间检查一个 `int` 的可写范围。 |
| `sys_exec` | 4 | 接收名称、名称长度、映像地址和大小。内核启动路径可进入 `do_execve()`；来自 U 态的请求先检查两个缓冲区的可读范围，检查失败返回 −3，通过后当前返回 −20。 |
| `sys_yield` | 10 | `do_yield()` 设置 `need_resched`。返回用户态前由 `trap()` 检查此标志并调用调度器。 |
| `sys_kill` | 12 | 把目标 PID 交给 `do_kill()`。进程层设置退出标志，并在目标处于可中断等待时将其唤醒。 |
| `sys_getpid` | 18 | 读取并返回 `current->pid`。 |
| `sys_putc` | 30 | 对 `arg[0]` 调用一次 `cputchar()`，然后返回 0。用户态 `cprintf()` 格式化出的字符经此路径输出。 |
| `sys_pgdir` | 31 | 当前内核只有页表打印函数的声明，处理函数返回 −20；此版本尚无页表输出。 |

用户态 `exec` 有一个比“地址可读”更严格的条件。当前 `do_execve()` 在调用 `load_icode(binary, size)` 前先切走旧页表，旧地址空间的最后一个引用被释放时还会回收映射。即使在系统调用入口验证过 `binary`，之后也不能再按原用户地址读取 ELF。要支持用户发起的程序替换，装载器需要在旧映射有效期间取得所需内容，或在旧映射仍有效时构建新映像，同时检查 ELF 各段是否落在输入缓冲区内。[进程与装载代码](../code/kern/process/proc.c)

首次启动走另一条入口。此时 `user_main()` 仍是内核线程，传入的是内核镜像中的 ELF。`kernel_execve()` 用 RV64 寄存器传递完整地址，在 `a0` 放 `SYS_exec`，在 `a7` 放断点处理分支识别的标记 10，随后执行 `ebreak`。我们用 `.option norvc` 固定该指令为四字节，与断点分支的 `epc += 4` 一致。因此启动日志里紧跟 `kernel_execve` 的 `Breakpoint` 有明确来源；进入 U 态后，程序通过 `ecall` 发起日常系统调用。

## 六、扩展练习 Challenge：Copy-on-Write

### 6.1 设计与状态转换

以下是普通 `fork` 的 COW 设计草案，尚待实现和验证。要区分两类信息：VMA 记录该段是否允许用户写入，页表项记录 CPU 此刻能否直接写入。可以给原本可写、暂时受保护的映射设置软件标志 `COW`。原本只读的代码页则保留只读权限，写入时不能转为可写。

| 当前状态 | 事件与条件 | 下一状态和内核操作 |
|---|---|---|
| 私有可写 | 普通 `fork` 成功 | 父子映射指向同一物理页，两侧都清除写权限并设置 COW 标志。增加映射引用，刷新父进程旧的可写 TLB 项。 |
| COW 共享 | 任一进程读取，或再次 `fork` | 读取沿用原映射；再次复制进程时给新增映射增加引用，现有各方保持写保护。 |
| COW 共享 | 发生写缺页，VMA 允许写入，仍有其他映射 | 分配并复制一页，只替换写入方的映射、恢复它的写权限并清除其 COW 标志。更新引用和 TLB 后，重试原写指令。 |
| COW 保护、仅余一个所有者 | 发生写缺页，VMA 允许写入，内核已确认物理页独占 | 原地恢复写权限并清除 COW 标志，刷新映射后重试；无需复制。 |
| COW 保护 | 一个进程退出或撤销映射 | 撤销本方映射并减少引用。仍有所有者时保留物理页，最后一个引用消失后才回收。 |
| 普通只读 | 对只读代码或数据执行写入 | 进入访问权限错误路径，页表保持只读。 |

处理写缺页时应在保护映射及其引用的临界区内重新核对当前页表项。复制新页失败时，旧映射和引用仍须有效。实现后可让父子先读取同一初值，再分别写入不同值并交换执行顺序，核对两侧可见值。另用独立用例检查真正的只读段始终拒绝写入。

## 七、实验问题与总结

### 7.1 用户程序何时被预先加载到内存中？与常用操作系统有何区别？

用户 ELF 的字节随内核镜像一起进入物理内存。构建时，Makefile 先使用 `tools/user.ld` 链接每个用户程序，随后在链接 `bin/kernel` 时用 `--format=binary $(USER_BINS) --format=default` 把这些 ELF 作为数据嵌入内核，再由 `objcopy` 生成 `bin/ucore.img`。QEMU 将镜像放入内存时，用户 ELF 已经可由内核寻址。此时还没有为它建立用户栈，也没有 CPU 正在执行它的入口。[构建规则](../code/Makefile) · [用户链接脚本](../code/tools/user.ld)

把 ELF 装入具体进程发生在后面。默认的 `user_main()` 调用 `KERNEL_EXECVE(exit)`，通过链接器符号取得 `exit` 映像的起点和长度。`load_icode()` 按 ELF 程序头为可装载段建立用户映射、复制文件内容、将段尾需要补齐的区域清零，并准备用户栈。首次进入 U 态还需要有效的 `sp`、`sepc` 和 `sstatus`。第 5.1 节的断点正好落在两者之间：内核已经找到嵌入的程序，首次返回现场仍有三个字段要填写。[程序选择和 ELF 装载](../code/kern/process/proc.c)

以 Linux 上从文件系统启动普通 ELF 为例，shell 启动外部程序时可以通过 `execve()` 指定可执行文件的路径。内核在执行请求到来时建立该程序的地址空间，文件映射的页面通常可以在首次访问时按需调入，因此安装或更换普通应用无须重新链接内核。Lab5 将测试程序预先嵌入镜像，使第一个用户进程可以在还没有可执行文件路径查找和文件装载接口的阶段启动；更换嵌入的程序内容则需要重新构建镜像。[Linux execve(2)](https://man7.org/linux/man-pages/man2/execve.2.html) · [Linux 内核内存管理文档](https://docs.kernel.org/admin-guide/mm/concepts.html)

### 7.2 本实验列出了多少个目标函数？

按题面四个基础模块逐项计数，模块一有 11 个（异常处理 1 个、分发器 1 个、处理函数 9 个），模块二有 8 个，模块三有 4 个，模块四有 3 个，共 **26 个不同的 C 函数**。例如模块一的 `sys_exit()` 接收系统调用参数，模块四的 `do_exit()` 管理退出时的进程状态，两者分别计数。另有一项点名要求的汇编宏 `RESTORE_ALL`。Lab2/3/4 的迁移和 COW 扩展没有列出固定的新增函数个数；COW 会复用模块三的页表复制路径，并增加对写缺页的处理。
