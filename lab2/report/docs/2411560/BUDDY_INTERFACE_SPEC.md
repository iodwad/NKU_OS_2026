# Buddy System 接口规约

状态：接口分析稿；尚无 Buddy 实现、Buddy 测试执行或内核集成结果。

依据：本目录从 `../code` 复制的实际源码，39 个工程文件；带行号全文见 `evidence/source_numbered.txt`。本规约只约束可观察行为、状态和合法性，不指定链表、数组、树或其他数据结构。

## 1. 框架接口与调用边界

`kern/mm/pmm.h:15–31` 定义管理器：

| 成员 | 必须提供的能力 |
|---|---|
| `name` | 有效的分配器标识字符串，用于现有输出。 |
| `init(void)` | 初始化一个尚未管理资源的分配器实例，准备内部状态。不能要求通过尚未就绪的自身 `alloc_pages()` 才能完成初始化。 |
| `init_memmap(struct Page *base, size_t n)` | 将给定的、此前未注册的可用连续物理页区间纳入管理。不能要求调用者只提供 2 的幂页数或大块对齐起点。 |
| `alloc_pages(size_t n)` | 支持正整数页数请求，返回至少覆盖请求的连续物理页区间的首描述符，或返回 NULL。不能只接受 2 的幂请求而忽略非幂请求的适配。 |
| `free_pages(struct Page *base, size_t n)` | 接收首描述符和页数，按明确的分配/释放契约归还资源，恢复可用性和正确计数。 |
| `nr_free_pages(void)` | 返回当前真正可再次分配的物理页数量，单位为 4096 字节页面。 |
| `check(void)` | 检查本分配器的接口和 Buddy 不变量；正常返回代表检查未失败，不能把测试遗留的已分配页或改动的全局量留给内核。 |

公共包装函数在 `kern/mm/pmm.c:44–63`，只转发，不增加对齐、长度修正、分配记录或锁。`alloc_page()/free_page()` 在 `pmm.h:42–43`，分别等价于请求/释放 1 页。

当前启动链为 `pmm_init()` → `init_pmm_manager()` → `page_init()` → 管理器登记 → `check_alloc_page()`。`pmm.c:37` 仍选择 `default_pmm_manager`。本轮没有修改此选择。`page_init()` 目前缺失，因此不能声称已观察到实际登记区间或次数。

## 2. 地址、描述符与字段约定

依据 `mmu.h:9–13`、`pmm.c:15–22`、`pmm.h:83–108`：

- `PGSIZE=4096`，`PGSHIFT=12`。
- `nbase=DRAM_BASE/PGSIZE`；DRAM_BASE 为 `0x80000000`，故 nbase 为 `0x80000`。
- `npage` 在当前转换函数和测试中的语义是物理页号排他上界；不是 RAM 实际页数，描述符数为 `npage-nbase`。
- `pages` 是描述符数组的内核虚拟地址，不是空闲区起点。
- `page2ppn(p) = p-pages+nbase`；`page2pa(p) = page2ppn(p)<<12`。
- `pa2page(pa) = &pages[(pa>>12)-nbase]`。现有实现只检查上界，没有检查 `PPN(pa)<nbase`，因此调用方不能拿低于 DRAM 的地址去试探。
- `PADDR(p)` 得到描述符自身所在 RAM 的地址；`page2pa(p)` 才是被描述的物理页地址。二者不可混用。

例如 PA `0x80203000` 的页号是 `0x80203`，对应 `pages[0x203]`。`p+1` 表示下一个物理页的描述符；它在 C 内存中移动的是 `sizeof(struct Page)`，不是 4096 字节。

`kern/mm/memlayout.h:34–55` 的含义：

| 字段/宏 | 约定与边界 |
|---|---|
| `ref` | 引用计数。现有分配测试要求新分配页 ref=0；分配操作本身不等于外部引用。ref=0 不能单独证明页面空闲。 |
| `flags` / `PG_reserved` | bit 0 表示保留页。保留页不得被普通分配/回收。不能把保留位偷作 Buddy 阶数或普通已分配标志。 |
| `PG_property` | bit 1 标识空闲块头。分配成功返回的页不能仍是可分配空闲块头。位为 0 也不能单独证明该页已分配，因为空闲块内部页通常同样为 0。 |
| `property` | 现有 First-Fit/Best-Fit 检查把它读作空闲块页数。若 Buddy 私有表示要复用为阶数，必须明确隔离语义并使用自己的检查逻辑，不能让原测试把阶数当页数。是否复用此字段不在本轮定案。 |
| `page_link` / `le2page` | 可供侵入式双链表使用，不强制 Buddy 使用它。若使用，一个节点同一时刻只能属于一个有效组织；不能重复挂接。 |

本轮保持 struct Page、状态位和转换函数不变。后续若需要额外元数据，应先明确生命周期和空间来源；不能因未有可用堆分配器而递归依赖自身初始化。

`libs/list.h:82–106` 说明 `list_del()` 不会将被删节点重新置为独立空表头，`list_del_init()` 才会；使用这些工具时不能把残留 next/prev 误当当前成员资格。它们没有自动维护 Page 标志、页数或互斥保护。

## 3. 初始化输入：不存在二次幂保证

`pmm.c:44–46` 原样转发 `(base,n)`；其中“连续 100 个页”的中文批注是例子，真实参数是 n，不是常量 100。`default_pmm.c:18–42` 仅断言 n>0 和各页原先 Reserved，没有要求 n 为 2 的幂，也没有断言大块对齐。

结论：

1. `base` 指向 struct Page，并非一个供直接检验 `%4096` 的页面数据指针。它所描述的物理页天然按页编号；这只保证 4 KiB 页粒度，不保证 8/16/... 页块边界。
2. 例如页号起点为 `0x80301`、长度 13 的有效登记不能直接舍掉尾部，也不能向外扩成 16 页。所有 13 页都须恰好纳入可管理集合，边界之外不得触碰。内部如何表示不作限制。
3. 当前缺失 page_init，无法确认未来实际只调用一次。管理器签名也没有单区间限制；First-Fit 登记逻辑会累加 nr_free，而不是每次重置。因此 Buddy 必须能够连续登记多个互不重叠的合法区间，不清空旧登记或已有分配。
4. 登记次数不等于 Buddy 合并域个数。相邻登记是否允许合并须遵守明确的域边界策略；任何含空洞、未注册页或保留页的父区间一律不能合并。

合法调用前提：pages/nbase/npage 已有效，n>0，`[base,base+n)` 完全位于描述符数组和实际可管理内存内，无溢出；所有页由调用方确认为可用、尚未登记。当前 First-Fit 还要求它们先标为 Reserved，再由登记函数解除此区间的保留状态。不能解除区间外 OpenSBI、内核镜像、启动页表或 Page 数组的 Reserved。

重复或重叠登记是非法输入，不得静默重复计数。应在状态改变前诊断/拒绝；不要求把错误输入当成一次合法释放。

## 4. 请求 n 页与 Buddy 二次幂容量的差异

这里必须区分“已从源码确认的约定”和“后续实现需要明确选择的适配契约”。

已确认：pmm.h 注释允许 `allocate >= n pages, depend on the allocation algorithm`；但签名只返回 Page*，不返回实际容量。包装函数也不会替调用者把 free 的 n 改成实际容量。First-Fit 的具体实现是恰好扣除 n 页，其测试还依赖部分释放。

所以不能单凭签名就声称 Buddy 必须等同 First-Fit，也不能偷偷把任意 n 当作整块容量。规约允许下面两种外部容量策略，但**实现及测试前必须固定一种并写入接口说明**：

| 外部容量策略 | `alloc_pages(3)` 实际独占容量 q | 对应释放和计数要求 |
|---|---:|---|
| 精确页数适配 | 3 | 只对外独占 3 页；内部即使暂取 4 页，剩余页也不得失踪或与已分配区重叠。完整释放原请求时恢复 3 页。 |
| 二次幂容量适配 | 4 | 必须明确调用者独占 4 页、其中额外 1 页也不能再分配；`free_pages(base,3)` 与原申请配对时必须能归还这 4 页，不能只释放 3 页造成泄漏。元数据或规则必须能无歧义恢复容量。 |

二次幂策略一般为 `q=2^ceil(log2(n))`。这是接口容量定义，不是实现算法代码。只允许与声明一致的策略，不能分配时按 q 扣账、释放时按 n 加账。

`free_pages(base,n)` 对相同首址、相同原请求 n 的完整释放至少要可用。若支持“调用者改传实际容量 q”，应另外明确哪些组合有效，避免错长度也被接受。

**部分释放是另一项独立决策**：`default_check()` 确实执行 `alloc_pages(5)` 后 `free_pages(p0+2,3)`，这证明 First-Fit 支持该路径，不证明 Buddy 可以直接复用这个测试。Buddy 若要承诺同等公共页区间行为，就必须正确支持不对齐/非幂子区间释放及剩余所有权；若只支持匹配的整块释放，必须明确该限制，不能调用 First-Fit 的专用 check 后通过删断言规避不兼容。本轮不替未来整合悄悄选择这一策略。

无论选择哪种容量策略，都不要求按最低地址返回、匹配 First-Fit 或 Best-Fit 的选块顺序，也不以这些具体算法的碎片形态作为 Buddy 正确性标准。

## 5. 可观察状态与空闲页统计

令 F 为 `nr_free_pages()`，R 为已登记可分配物理页集合，q 为上一节声明的实际独占页数。

| 操作 | 必须观察到的结果 |
|---|---|
| 一次启动期 `init()` | 内部状态有效，尚未登记资源时 F=0；此时分配正数页返回 NULL。不能承诺对仍有活动分配的实例随意重置安全。 |
| 登记互不重叠的 n 页 | 可用资源增加恰好 n 页，F 增加 n；原有分配和其他区间不变。不能为凑幂而丢页或增加假页。 |
| 成功分配 n 页 | 返回有效首描述符，连续 q 页均在 R 内、非保留、此前空闲，不能与任何未释放分配重叠；至少覆盖 n 页，F 精确减少 q；ref/空闲头状态满足既定约定。 |
| 资源不足、无合法候选块或请求超过支持容量 | 返回 NULL。F、已有分配、可用范围与计数不变；失败不得留下拆分后漏失的资源。内部表示即使变化也须保持等价且可继续分配。 |
| 匹配的完整释放 | 恰好归还该分配仍拥有的 q 页，F 增加 q；已释放页不再属于原调用者，可用于后续分配/合并；其他活动分配不变。 |
| 合法部分释放（若声明支持） | 只归还指定子区间，F 只增加其归还页数，不能同时归还仍在用的兄弟页。 |
| `check()` 正常返回 | 无漏页、重复页或计数漂移；临时申请均归还，临时改动的全局量恢复。允许等价的内部表示，不要求节点顺序完全相同。 |

F 是页数，不是空闲块数、阶数和、最大连续块、字节数或剩余请求容量。拆分和合并不改变 F，只有资源登记、实际占用或归还才改变 F。

在没有额外显式保留元数据页的本接口模型下，任何时刻满足：`|R| = F + 所有未释放分配的实际独占页数之和`。若未来确需占用 R 内页面保存元数据，必须显式扩充账本、说明其保留及回收规则，不能把隐藏消耗当成正确结果；本轮没有授权修改 page_init 的保留区布局。

F 足够大不意味着一定能成功申请大块：碎片、对齐和独占容量 q 都可能阻止申请。F=10 但只有分散单页时，申请连续 8 页可以失败。

n=0 是非法请求，现有实现使用 assert(n>0)，不能把它当有效零页分配。大到无法表示的 n、移位阶数或地址计算必须在溢出/未定义行为之前处理；资源不足的正常失败与非法释放的诊断应区分。

## 6. 对齐与合法伙伴

本规约采用物理页号坐标说明标准 Buddy 块不变量，不以 C 描述符地址做异或：

- 一个阶 k 的原生 Buddy 块容量为 q=2^k 页，物理页号首址 p 满足 `p mod q = 0`；其物理地址按 q×4096 对齐。
- 候选伙伴首页号为 `p XOR q`；两个块大小相同，是同一个对齐 2q 父块的两半，而非任意相邻块。
- 例：q=4 时，页号 0x80304 与 0x80300 是伙伴；0x80304 与相邻的 0x80308 不是伙伴。
- 只有双方都是完整、空闲、同阶、未被占用的块头，且整个父区间属于合法已登记合并域，才可合并。不能仅凭数值异或落在 `[nbase,npage)` 就认定存在伙伴。
- 伙伴位于未登记洞、保留页、域外、不同阶、已分配块内部或混合占用父区间时，禁止合并。
- 合并后的头为父块较低页号，容量为 2q；不得继续把旧子块头同时当作两个独立空闲块。

如果后续选择相对于 arena 起点 A 的 Buddy 坐标，必须明确所有对齐与伙伴运算都基于同一个 `p-A`，并说明如何满足承诺给调用者的物理对齐；不能把任意首个空闲页当成已满足大块物理对齐的零点。当前 `nbase` 对常见低阶对齐并不等于“任意登记起点也已对齐”。

精确 n 页适配的对外区间可以由若干原生块组成；上述二次幂约束针对原生 Buddy 块，不意味着每个任意 n 请求自身都必须是二次幂块。

## 7. 不可破坏的边界

- 保持 pmm_manager 函数签名、公共包装和 Page 转换约定；不能把 init_memmap 的 base 当物理地址或把 n 当字节。
- 不分配保留页、不越界、不跨洞、不重复占用、不重复回收；释放不应擅自覆盖页面数据，调用方是否清零是另一契约。
- 不修改队友 page_init/Best-Fit，不改变官方目录或 Lab1，不改现有 First-Fit/Best-Fit 测试使 Buddy 看似通过。
- 不以 CPU/组件测试代替 RISC-V 内核集成验证，不以对象文件编译代替链接/运行成功。
- 当前 pmm 包装没有锁；本次目标是当前单 hart/串行调用场景，不自动宣称多核、中断重入安全。若扩大场景，需另定同步约定。
- 本轮没有锁定容量策略、部分释放策略或最大阶；这些是后续必须明确的外部契约项，不是选择某种数据结构的理由。

## 8. 后续测试覆盖清单（未执行）

1. 空初始化、空分配失败、单页登记/申请/归还。
2. 非幂大小和不按大块对齐的登记；全部 n 页可追溯，无向外扩张、尾部损失。
3. 多次登记：分离区间、相邻区间、带洞区间；顺序改变不应重置旧资源。
4. 各阶精确容量、最大合法阶、阶数边界；申请前后 F 精确变化。
5. 非幂请求 3、5、6、9 等；按已确定的 q 策略检查独占范围及同请求配对释放，不允许隐藏泄漏。
6. 逐步拆分、合法伙伴归还合并、多级合并、逆序释放；全释放后恢复全部初始资源。
7. 物理相邻但不是伙伴、大小不同的相邻块、伙伴已分配、伙伴跨洞/保留区/域边界，均不得误合并。
8. 分配耗尽、F 不足、F 足够但无合法大块、极大 n/溢出边界；失败后账本和已有分配不变。
9. 所有同时存活分配两两不重叠、ref/状态与声明一致、PA↔Page 往返正确。
10. 整块匹配释放；部分释放按声明分别验证“正确支持”或“明确诊断”，不得无意释放整块的其他存活页。
11. 重复释放、错长度、非头地址、越界、保留页、未登记页和重叠登记的非法输入诊断。
12. 重复运行 check，随机申请/释放的模型账本核对；结束时 F 和资源集合恢复，不依赖固定返回顺序。
13. 本机逻辑测试（如采用）和 RISC-V 编译/内核 QEMU 测试分别报告，后者需在队友模块具备可编译状态并明确授权切换后才执行。

测试只规定输入、期望结果与不变量，不检查是否采用链表、数组或树，不把私有容器形状当成唯一正确答案。
